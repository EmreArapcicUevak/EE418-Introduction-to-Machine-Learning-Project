  \section{Introduction}
    \subsection{What is the problem?}
      \begin{frame}{What is the real-world problem?}
        In the modern housing market, both \textbf{apartment sale prices} and \textbf{rental prices} can vary drastically depending
        on factors such as location, size, number of rooms, building condition, and surrounding amenities. \newline \pause

        However, in many listings, especially on local platforms, price information is often missing, incomplete, or inconsistent.
        This makes it difficult for potential buyers, tenants, and even property owners to assess the true value of an apartment or to set a fair and competitive price.
      \end{frame}

    \subsection{What is our solution?}
      \begin{frame}{Our Solution}

        \begin{columns}[T]

          \column{0.45\textwidth}
            \begin{block}{Proposed Approach}
              \begin{itemize}
                \item[$\bullet$] Predict apartment \textbf{sale} and \textbf{rental} prices
                \item[$\bullet$] Use publicly available real-estate data
                \item[$\bullet$] Provide transparent price estimates
                \item[$\bullet$] Display a ``fairness score`` for listings
              \end{itemize}
            \end{block}

  \section{Dataset}
    \subsection{How did we get our data?}
      \begin{frame}{How did we get our data?}
        As of \today~there is yet to be any good publicly available data for apartments that were sold or rented out for Bosnia and Herzegovina. \newline \pause

        The closest we got to finding public data about apartments in Bosnia and Herzegovina was by using the "Registar cijena nekretnina" that can be found
        here (\textit{https://www.katastar.ba/rcn/preglednik/})
      \end{frame}

      \begin{frame}{The problem with the registry}
        So there is a public registry of every apartment sales across the federation of Bosnia and Herzegovina. \newline

        So can we use it? \newline \pause

        Short answer\ldots \textbf{no} \newline \pause

        Long answer\ldots The data available on the registry, while plentiful, lacks a lot of details needed for us to train a machine learning model \newline \pause

        This is why, the only available work done on this topic was just a paper demonstrating the price changes and average prices of real estate sales across the region.
      \end{frame}

      \begin{frame}{So how did we get our data?}
        Because of the lack of data available to the public we went with webscraping the data off popular websites for real estate in Bosnia:
        \begin{itemize}
          \item[$\bullet$] OLX.ba
          \item[$\bullet$] Nekretnine.ba
        \end{itemize}

        \vspace{0.5cm}
        \pause
        Out of which we were only able to utilize \emph{OLX.ba} as we lacked the time to further pre-process the data from Nekretnine.ba
      \end{frame}

    \subsection{Feature Creation}
      \begin{frame}{Using coordiantes}
        So we showed that coordinates are an important feature to have, however we did not cover how to use them. \newline \pause

        One way that we picked to work with coordinates was that first we would load the so-called points of interests of a region,
        then we would find the closest point to some apartment, calculate the distance from the point to the apartment, and use that as a feature. \newline \pause

        But what is a point of interest? \newline \pause

        A point of interest can be any amenity that could or would play a role in the pricing of the apartment.
      \end{frame}

      \begin{frame}{Example of POI}
        \begin{figure}[H]
          \centering
          \includegraphics[width=0.8\textheight]{Images/distribution_of_bus_stops}

          \caption{All bus stops in Canton Sarajevo}
          \label{fig:Bus Stops in Canton Sarajevo}
        \end{figure}
      \end{frame}

      \begin{frame}{Problem}
        \noindent However, using coordinates opens us to another set of problems. \newline

        \begin{itemize}
          \item What if the given apartment was mislabeled?
          \item What if the apartment was marked as being outside of canton Sarajevo?
          \item What if the apartment was an agency?
        \end{itemize}

      \end{frame}

    \subsection{Data cleaning (Again)}
    \begin{frame}{The idea}
      So how would we go about cleaning the apartment? \pause \newline

      Well there is one simple idea, and that is by checking the location of the apartment and comparing it with its labeled
      municipality that it claims to be in. \pause \newline

      This is not a perfect approach for removing agencies since agencies can still be in the same municipality that they are selling the apartment.
      However, the method does work. \newline \pause

      One nice benefit of this method is that it also lets us remove faulty apartments and in some cases it even helped us remove an apartment that did not exist.
    \end{frame}

    \subsection{Picking the best Model}
      \begin{frame}{Picking the Best Model}

      \begin{itemize}
        \item \textbf{Primary criteria}
          \begin{itemize}
            \item Good generalization on unseen (test) data
            \item Lower test error than the baseline model
          \end{itemize}

        \pause
        \vspace{0.5em}

        \item \textbf{Model comparison strategy}
          \begin{itemize}
            \item Highest test $R^2$ (variance explained)
            \item Lowest test NMAE (average prediction error)
            \item NRMSE used to resolve close cases
          \end{itemize}

        \vspace{0.5em}
        \pause

        \item \textbf{Final decision}
          \begin{itemize}
            \item \textbf{Sales model:} Support Vector Regression
            \item \textbf{Rental model:} K-Nearest Neighbors
          \end{itemize}
      \end{itemize}

      \end{frame}
